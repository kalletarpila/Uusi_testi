Reachability: with nine questions per group, answering 4 for both candidate
groups and 3 for the others yields 36/36 versus 27/27. By reviewing ordinary
answers one can assign these scores to any target pair. All 30 directed
different-pair transitions are therefore reachable (including disjoint pairs),
in both modes. Tests must exercise both target winners and complete Phase 2.
There are no excluded directed pair changes under these permitted multi-answer
edits. This is branch/transition coverage, not exhaustive mathematical coverage.

State policy: ordinary answers by question ID are authoritative. Scores,
yes counts and research records are recalculated from those latest answers.
Review with no answer change retains the active TB state, question order,
selections and current index. Any actual ordinary answer change invalidates
the current TB, even if the same pair remains eligible or the value is later
changed back. Cached question data, ordinary answers and invitation metadata
are retained. New/legacy TB aggregates remain separate from Phase 1 totals.

CRITICAL REVIEW AND CORRECTIONS
The return handler existed at initial HEAD, but the POST dispatcher did not
call it from either TB mode and no usable return control was rendered. The
ordinary-question return-to-TB block was disabled. Reproduction before the
application changes failed in both modes on the missing rendered control.
The old handler also depended on overlapping point/question/answer backups;
legacy reinitialization could restore answers from an obsolete comparison.
New TB Back deleted the answer and its point. Its buttons did not display a
stored choice, and increment-only answer handling was unsafe for replacement.
Ordinary Next could skip an unanswered question or advance past the last one.

Both modes now expose the existing-style return control, including TB intro.
The session retains one real round plus its review-state marker and a context
fingerprint covering ordinary answers, candidates and the actual ordered TB
questions/mappings. Back/forward preserves answers; a selected CSS class and
aria-pressed expose the stored left/right choice or legacy 1-6 value. Replacing
an answer writes its indexed record and derives the counters again. Previously
answered questions have a forward control and need no new answer submission.
Ordinary Next requires an existing answer and evaluates completion at the end.
Incomplete TB completion, wrong-state requests, forged targets, mixed actions
and stale tokens cannot bypass the round. Existing POST/redirect/GET remains.
Invalid primary state fails explicitly; only derived totals are repaired.
Legacy fallback requires questions for BOTH candidates, avoiding an apparently
valid result when only one side is configured. No scoring rule was changed.

The fingerprint is intentionally not a migration of pre-update active rounds.
An old active TB session without the new context fails safely and needs reset.

equal or nearby leaders still admit only the highest two. Equal ordering may
favor the first group; new TB counter ties use original Phase 1 scores then
existing order. Legacy final ties retain the existing random choice. These
are documented algorithm limitations, not approved changes in this task.

by these routes. Tests verify the active gap-2/gap-3 boundary explicitly.
